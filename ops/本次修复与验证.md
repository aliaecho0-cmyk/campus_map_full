# 2000 人高峰：本次修改与上线前交接

日期：2026-09-16。对象：https://www.clubfairmap.com/ 。初次检查基线：`aliaecho0-cmyk/campus_map_full` 的 `main`，提交 `d8bb767c2faa4a05162b3ed8b8e54c6b22e77677`。准备 PR 时已整合最新 `main` 的 `aeb12e8143fe7bdd108c14db70c8eb312a0d83ab`，保留同学的 WebP 图片、名称展示修复和浏览进度即时反馈。

## 先看结论

截图中的香港 4 vCPU / 8 GiB 可以作为当前架构的容量验证起点，不能据此承诺 2000 人同时首次打开都流畅。目前没有服务器 CPU、内存、磁盘或队列的现场监测结果，因此不能断言硬件算力不足，也不能断言数据库已能承载目标流量。

已确认有可减少的前端下载量，以及登录请求阻塞原始启动流程的问题。按流量计费的 100 Mbps 是出口上限，不是保证带宽；若 2000 人在一分钟内各首次下载 1 MB，理想出口需求就约为 267 Mbps。这个例子只说明带宽约束，不是实际页面大小测量，也不是每位用户等待时间。

初次验证时仅修改本地代码副本、添加测试和运维交接材料；后续提交与 PR 状态以 GitHub 记录为准。未替换线上文件、未登录 ECS、未改 Nginx、未访问业务数据库、未发起生产压测。下文中的“通过”只指对应的本地检查，不等于上线或容量验收。

## 1. 当前证据与边界

| 项目 | 本次观察 | 不能据此推断的事 |
|---|---|---|
| ECS 配置 | 用户截图：香港 D、4 核 8 GiB、Ubuntu 22.04、40 GiB ESSD AutoPL、按流量计费 100 Mbps | 实际可用出口、校园到香港的吞吐、生产 CPU 和数据库瓶颈 |
| 域名入口 | `www` 与裸域 HTTPS 均可返回首页，HTTP www 跳转 HTTPS | 两个域名共享浏览器身份；事实上它们的 localStorage 分离 |
| 初次线上检查的入口脚本 | `/assets/index-B0qICjgE.js` 实际下载 750,401 字节；请求接受压缩，但响应未见 Content-Encoding | 历史检查快照，不表示同学后续部署仍是此版本；也不能把单文件当成全部首屏体积 |
| 单次下载耗时 | 上述脚本在检查机器的网络上约 8.6 秒 | 不是校园网测量，不代表所有人的耗时 |

原审计快照的 NPC 四张图合计约 3.36 MB、两张底图约 0.98 MB。准备 PR 时，上游同学已将图片转成 WebP，相关四张 NPC 约 0.263 MB、两张底图约 0.570 MB，这些优化已保留，不能再用旧图片体积判断当前版本。两份字体仍合计约 1.33 MB、音乐约 2.38 MB。部分资源按页面或交互加载，不能把构建目录总大小当成首屏实际下载量。应记录新用户首次进入至可操作时的真实网络瀑布，再判断剩余优化空间。本 PR 本身不新增图片、字体或视觉设计变更。

## 2. 已做的本地修复

- **地图不等待登录响应。** `main.js` 先启动静态页面；奖励页和浏览记录各自等待共享的登录请求。后端慢时不应把整个静态地图挡住。
- **接口请求最多等待 8 秒。** 超时覆盖响应头和响应体，提供可理解的提示；没有新增自动重试写入的逻辑。客户端超时不代表服务器一定没写入。
- **防止身份被迟到响应覆盖。** 后台学生登录完成时，如果用户已经登录工作人员账号或退出，忽略旧学生登录结果。
- **奖励页可重试、可清理。** 初次登录失败时提供重试；异步取得活动时间后倒计时继续工作；挂载返回可销毁对象，离开页面时清理定时器和订阅，避免滞留页面继续工作。
- **扫码与二维码库按需下载。** 普通地图入口不再预先下载工作人员扫码库；只有展示领取码时加载二维码生成库。工作人员身份检查网络失败时保留会话并允许重试，只有明确鉴权失败才清除会话。
- **音乐延后创建播放器。** 不再在模块初始化时预加载音乐。但原本选择语言后请求播放的行为仍保留；音乐仍可能消耗后续带宽，不能把此修改理解成活动全程不下载音乐。

代码验证采用 Code 工作流：先做范围明确的修改，再运行测试与生产构建，并独立复核异步页面生命周期。所有修改待前后端同学审阅和测试环境验收；不是已部署补丁。

## 3. 如何在同学电脑验证

先确认待合并代码与上述基线的差异，使用分支审阅；不要把整个旧副本覆盖到同学已经更新的代码上。依赖未新增，锁文件未改。以下验证使用 Node 24.20.0；页面测试使用 Node 的模块加载钩子，建议用 Node 24 执行。测试预览必须保持 `frontend/.env.production` 的 `VITE_API_BASE=` 为空（同源），且不要通过命令行环境或 `.env.production.local` 将它覆盖为生产 API 地址。

```bash
cd frontend
npm ci
npm test
npm run build
```

测试包含：响应头卡住、响应体卡住、成功请求清理超时器、代理非 JSON 错误保留状态、学生/工作人员登录竞态、退出登录后的迟到响应、登录去重、奖励页迟到截止时间、离开奖励页后不继续请求奖励接口，以及新增的“等待登录期间保留待确认进度、只写入一次”和“登录失败清理待确认进度、不发起浏览写入”。它们使用模拟网络和简化的页面容器，不是真实浏览器端到端测试。

PR 准备时的结果：**11 项测试全部通过，生产构建通过，预览脚本语法检查通过。** 服务器巡检脚本此前已通过 Bash 语法、帮助入口和内嵌 Python 语法检查，尚未在实际 ECS 执行。最新入口构建文件为 `index-CEVFQUCC.js`，362.34 KB，构建器估算 gzip 102.79 KB；早先 348.21 KB 的结果对应未整合上游新功能的旧基线，不应混用。

另外提供一个**只在本机监听**的人工验证环境，静态文件来自新构建，所有 `/api/` 故意等待 30 秒，不连接生产服务器或数据库：

```bash
node scripts/preview-unavailable-api.mjs
```

打开 `http://127.0.0.1:4174`，选择语言、看地图与社团详情，检查约 8 秒后出现提示但地图仍可用；直接访问 `http://127.0.0.1:4174/#/reward` 检查失败提示与重试。使用 Ctrl+C 停止。

**本次浏览器验证工具超时，以上浏览器检查尚未完成。** 工作人员扫码、摄像头权限、按需脚本加载失败后的恢复，以及领取/核销“服务器已提交但响应丢失”的流程，也必须在隔离环境用测试身份验证。核销超时应核对最终状态，不可仅因错误提示就重复发奖。

| 第一批 | 后端同学 | 复核生产是否仍用仓库默认工作人员口令；如是，走安全变更流程替换。严校验摊位 ID、限制滥用与重复写入，统一运行/迁移数据库路径。不要把并发扩容问题只交给前端。 |

| 活动前 | 服务器 + 组织负责人 | 验证数据库一致性备份与隔离恢复；备份必须在实例以外。截图显示未启用释放保护、系统盘随实例释放，确认保护和费用告警；明确人工核销应急流程。 |

数据库就绪检查、默认口令治理、摊位合法性校验、设备身份防滥用、旧活动 ID/浏览缓存的隔离等**没有在本补丁内修复**。旧文档中的服务器 IP、规格、本机压测与单文件数据库复制不能直接当作本次上线依据。

若优化后出口仍是瓶颈，再比较提高可用出口与境外静态 CDN，依据校园网络实测选择。CDN 只承接公开静态文件，不缓存个人进度、身份或核销接口。没有 ICP 时不可直接配置中国内地加速范围；境外节点是否更快也没有保证。

域名统一也应安排迁移：当前 www 与裸域浏览器数据分离。活动入口先统一宣传 www；若已有真实领取进度分散在两个域名，不能不检查就强制重定向，避免学生认为进度丢失。

## 5. 关于香港与备案

域名买在腾讯云不妨碍解析至阿里云。阿里云当前说明香港服务器无需工信部 ICP 备案；但这不等于不受任何合规要求约束。阿里云同一指引还提示，香港/海外网站在中国内地可访问仍涉及开通后 30 天内公安联网备案，应由主办方向属地网安及学校确认办理主体和流程。隐私告知、数据最小化、素材/字体/音乐许可、学校地图与名称授权、奖品规则等仍需确认，不能保证“排除一切风险”。
